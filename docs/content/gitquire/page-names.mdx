title: Page names and links

description: Link-friendly file names, wiki links that always resolve, and links rewritten on rename.

When you create or rename a page or folder, GitQuire turns the new name into lowercase words joined
by hyphens: *Meeting Notes 2026* is saved as `meeting-notes-2026.md`. A new page keeps what you
typed as its `# Title`, so the readable name isn't lost.

- Folders that already exist keep their names; only new names are changed.
- Names starting with `.` or `_` are left alone.
- The rule applies to pages created in the editor, by agents and through the API alike.
- Set `GITQUIRE_NAMING=off` to keep names exactly as typed.

## Links keep working

`[[Meeting Notes 2026]]` finds `meeting-notes-2026.md`, because wiki links are matched the same way.
Renaming or moving a page rewrites the links that point at it, and the backlinks panel shows which
pages link where. See also [links and backlinks](../reference/core-concepts.md#links-and-backlinks).
Links in a page's properties count too, and are rewritten the same way.

To say how two pages relate, such as *supersedes* or *blocks*, use [typed links](./typed-links.mdx).

## Broken links

The broken-links button in the header shows how many links point to pages that do not exist. It
lists each missing page with the pages that link to it, so you can open them and fix the link.
Set `validation.links: off` in `.ok/config.yml` ([configuration](../reference/configuration.mdx))
to hide it. Links from agent folders (`.agents`, `.claude`, `.cursor`) are not listed, and neither
are links from `log.md` pages while **Ignore broken links in log.md** is on (the default).
