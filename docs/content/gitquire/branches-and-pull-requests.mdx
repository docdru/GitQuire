Day to day, everyone works on `main` and GitQuire commits and pushes automatically. For something
bigger, such as a new report that should be reviewed first, use a branch.

## The branch menu

The branch name next to the project name in the header opens the branch menu:

- **Switch everyone to** a branch. GitQuire runs one shared working copy, so switching moves every
  open editor to that branch; you're asked to confirm.
- **New branch…** creates a branch from the current one and switches to it. Names follow Git's
  rules, for example `report/q4-results`.
- **Open pull request…** pushes pending edits, waits until the branch is on GitHub, and opens a pull
  request into the base branch. You can mark it as a draft.
- **Open pull requests** lists the repository's open pull requests and links to them on GitHub.

Pull requests are opened by the GitHub App, so the App needs **Pull requests: read and write**. The
description names the person who proposed it.

## API

| Endpoint | Purpose |
| --- | --- |
| `GET /api/gitquire/branches` | Current, base, local and remote-only branches |
| `POST /api/gitquire/branches` | Create a branch: `{"name": "report/q4", "from": "main"}` |
| `GET /api/gitquire/pulls` | Open pull requests |
| `POST /api/gitquire/pulls` | Open a pull request from the current branch: `{"title": "…", "body": "…", "draft": false}` |

Switching uses `POST /api/git/checkout`. Any signed-in member may switch or create branches.
